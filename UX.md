# UX checklist

## 1. Purpose and priorities

- Is the purpose of this screen clear?
- Can users quickly find the actions or information that they want?
- Are important elements more visible than secondary details?
- Can you remove an element without making the task more difficult?

## 2. Organisation and navigation

- Are related items in groups, with headings that have a clear meaning?
- Do labels use the words of the users, not the words of the system?
- Can users see where they are? Can they see how to go back?
- Does navigation follow a logical and consistent order?

## 3. Visual hierarchy and consistency

- Are margins, alignment and spacing consistent?
- Are related elements closer together than unrelated elements?
- Do fonts, icons, colours and controls follow one consistent system?
- Do decoration, badges and dividers support the content? Do they compete with it?

## 4. Clear wording and understandable choices

- Do labels tell what each option does?
- Are current values visible, so that users do not have to remember them?
- Are units and scales clear where they are important?
- Is more explanation available for choices that are unfamiliar or that have large effects?

## 5. Controls and input

- Is it clear which elements users can operate?
- Does each control suit its choice: toggle, single selection, slider or text input?
- Can users complete the task with each input method that the plugin supports?
- Is the keyboard or controller focus visible? Is the navigation order predictable?

## 6. Feedback and state

- Does each action give clear feedback?
- Can users see the difference between the current value, the focused control and the options that are not available?
- Is it clear if a change applies immediately or needs a save?
- Do loading, success and failure states have an explanation where necessary?

## 7. Control, mistakes and recovery

- Can users cancel, go back or undo where applicable?
- Does the design prevent dangerous mistakes before they occur?
- Can users recover without the loss of unrelated work or choices?
- Does each error message tell the problem and what to do next?

## 8. Accessibility

- Can users read essential text and information in the intended viewing conditions?
- Can users understand states without colour alone?
- Can users operate the interface without a mouse, where keyboard or controller support is expected?
- Are labels, values and state changes available to the supported screen narration?

## 9. Efficiency without unnecessary complexity

- Can users do common tasks with few operations?
- Are useful presets or shortcuts available where they save time?
- Can advanced options stay available without making the main interface too full?
- Does the interface never ask users again for information that it already has?
